MISIÓN 02 · BASE DE DATOS II · SEMANA 09

Autenticación segura a nivel de servidor

MÓDULO 02 · SQL SERVER

Controla quién puede acceder al motor y qué puede hacer dentro de la base del proyecto. Se habilita el modo mixto, se crea el login analista_upla, se aplica el principio de menor privilegio y se protegen las cuentas de alto riesgo.

🔐 AUTENTICACIÓN 👤 LOGIN / USER 🛡️ MENOR PRIVILEGIO
OBJETIVO DE LA MISIÓN // QUÉ DEBES LOGRAR

🎯 META

Establecer políticas de autenticación seguras a nivel de servidor que restrinjan los accesos no autorizados al proyecto analítico, aplicando el principio de menor privilegio. El perfil analítico debe poder conectarse y solo consultar información.

CONCEPTOS CLAVE // LOGIN VS USER

LOGIN · NIVEL SERVIDOR

Verifica quién intenta conectarse al motor. Puede usar autenticación de Windows o credenciales propias de SQL Server.

USER · NIVEL BASE DE DATOS

Representa esa identidad dentro de una base concreta. Es el punto donde se asignan permisos sobre objetos.

ℹ

Relación importante: crear un login no concede acceso automático a todas las bases. Debe existir el usuario correspondiente en la base y asignarse solo los permisos necesarios.

ACTIVIDADES // PASOS DE LA MISIÓN
01

Habilitar el modo de autenticación mixta

Permite usar a la vez autenticación de Windows y logins de SQL Server.

  • Conéctate con autenticación de Windows.
  • Clic derecho sobre el servidor → Properties → Security.
  • Selecciona SQL Server and Windows Authentication mode.
  • Reinicia el servicio SQL Server (Configuration Manager → Services → Restart).
!

El cambio de modo de autenticación requiere reiniciar el servicio. No basta con cerrar y abrir SSMS.

02

Crear el login analista_upla

Login SQL destinado a consultar información del proyecto. Contraseña de laboratorio (ejemplo): Upla_Analitica#2026_Lab!

  • Activa Enforce password policy y Enforce password expiration.
  • En Server Roles: NO marcar sysadmin.
  • DEFAULT_DATABASE: ProyectoAnalitico_UPLA.
T-SQL · CREAR LOGIN
USE master;
GO

-- Crear el inicio de sesión SQL Server
CREATE LOGIN analista_upla
WITH
    PASSWORD = 'Upla_Analitica#2026_Lab!',
    CHECK_POLICY = ON,
    CHECK_EXPIRATION = ON,
    DEFAULT_DATABASE = ProyectoAnalitico_UPLA;
GO
03

Crear la base de datos del proyecto

Debe existir antes de asignar DEFAULT_DATABASE al login.

T-SQL
USE master;
GO
CREATE DATABASE ProyectoAnalitico_UPLA;
GO
04

Crear el usuario de base de datos

Asocia el login a un user dentro de la base del proyecto.

T-SQL
USE ProyectoAnalitico_UPLA;
GO
CREATE USER analista_upla
FOR LOGIN analista_upla;
GO
05

Asignar permisos de lectura (menor privilegio)

Un usuario que solo consulta reportes no necesita permisos de escritura ni administración. Se utiliza el rol db_datareader.

T-SQL
USE ProyectoAnalitico_UPLA;
GO
ALTER ROLE db_datareader
ADD MEMBER analista_upla;
GO
!

No asignes sysadmin a analista_upla. Permitiría controlar por completo la instancia y acceder a información fuera del alcance del perfil analítico.

06

Verificar permisos y proteger la cuenta sa

  • Comprueba que el login existe y está habilitado (consulta a sys.server_principals).
  • Verifica que el usuario pertenece a db_datareader.
  • Evalúa el estado de la cuenta sa. Si el entorno lo permite de forma segura y existe otra vía administrativa, deshabilítala.
ℹ

Antes de deshabilitar sa, confirma que tienes otra cuenta administrativa funcional y documentada. No bloquees tu propio acceso al servidor.

PRINCIPIO DE MENOR PRIVILEGIO // POR QUÉ IMPORTA
Concepto Pregunta que responde Ejemplo en el laboratorio
Autenticación ¿Quién eres? Validar el login analista_upla
Autorización ¿Qué tienes permitido hacer? Solo lectura en ProyectoAnalitico_UPLA
Auditoría ¿Qué actividad se realizó? Revisar conexiones y acciones
✓

Resultado esperado del módulo: modo mixto activo, login analista_upla operativo, usuario en la base del proyecto con rol db_datareader, sin privilegios de administrador, y cuenta sa evaluada/protegida.

MISIÓN 02 COMPLETADA

La autenticación segura combina una identidad verificable con permisos correctamente delimitados. Crear cuentas es solo el inicio; la protección real se consigue al asignar, probar y revisar los privilegios según el principio de menor privilegio.
